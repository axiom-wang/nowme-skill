# 修改（第 6 步）

## 按区块修改

1. **定位**：把主人的话对应到一个或几个 `data-nm-id` 区块。“第二块”“上面那段”“照片那里”这种说法不确定时，先列出区块让主人选：
   ```
   你说的是哪一块？
   1. hero —— 首屏：名字和招募卡
   2. projects —— 书递项目
   3. skills —— 技能清单
   ```
2. **只改目标区块**：其他区块的 HTML、文案、样式保持原样。需要改共用样式（例如整页配色）时，先告诉主人这会影响哪些区块。
3. **保留素材**：主人给的图片、原话、事实不因为改版式而丢掉；被替换下来的内容如果主人以后可能还要，先问一句再删。
4. **新信息**：主人在修改时说的新事实（例如“再加一句我拿过校赛二等奖”）属于“主人明确表达”，可以直接用；长期信息写回画像。
5. **复查**：改完重新 `nowme validate page` 和 `nowme preview page`，把变化用一两句话告诉主人。修改了接话点或一行介绍时，同步改 `card.json`。

常见修改的做法：

| 主人说 | 做法 |
| --- | --- |
| “换个颜色 / 风格” | 换主题类或覆盖颜色变量；风格大改时问一句“只改配色，还是版式也换？” |
| “第二块换成拼贴风” | 只重写该区块的结构和样式，内容不变 |
| “动效太多 / 太少” | 调整 `data-nm-motion` 与 `manifest.motionLevel`，增减循环动效 |
| “这句不像我说的” | 用主人的原话替换；brief 的“原话”同步更新 |
| “不要显示学校” | 删掉相关文字；brief 的“表达边界”同步更新；问主人这是只对这一页还是以后都这样 |
| “加一张照片” | 请主人提供图片文件，复制进 `page/assets/`（png / jpg / webp / gif，≤ 2 MB） |

## 做不到的请求与替代方案

页面运行在沙箱里，不能联网、不能存储、不能跳转顶层页面。遇到下面这些请求，如实说明，并给替代方案：

| 请求 | 为什么不行 | 替代方案 |
| --- | --- | --- |
| 放一个能运行的 demo / 嵌入我的网站 | 页面不能联网，也不能嵌 iframe | 截图或录屏动图放 `assets/`，加一个 `data-nm-href` 外链 |
| 显示我的 GitHub / B 站实时数据 | 不能联网 | 主人提供当前的数字或截图，静态写进页面并注明时间 |
| 留言板、点赞计数、访客统计 | 不能存储、不能联网 | 用平台的“想聊这个”；页面内互动只在本次浏览有效 |
| 背景音乐自动播放 | 平台关闭了自动播放；也影响别人浏览墙 | 用视觉表现音乐（唱片、波形），或外链到歌曲页面 |
| 用某款没在清单里的字体 | 只能用 Kit 字体清单 | 从清单里选最接近的一款；需要新字体由平台评估 |
| 把微信号写在页面上 | 联系方式由主人在应用内设置是否公开 | 引导访客点“想聊这个” |
| “帮我发布” / “帮我撤下” | Agent 没有发布权限 | `nowme submit` 后请主人在应用内确认发布；撤下也在应用内 |
| 写一些我没做过但听起来厉害的经历 | 不编造 | 用真实的、具体的小事；短而真比长而空好 |

不要静默忽略请求，也不要声称做到了。
